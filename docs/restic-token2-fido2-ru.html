Token2 Руководство по интеграции

Шифрование restic-бэкапов аппаратным ключом Token2 FIDO2

Данные можно расшифровать только физическим ключом Token2 — с вводом PIN и касанием. Пароль шифрования нигде не хранится — ключ вычисляет его по запросу.

О restic

restic — быстрая современная программа резервного копирования с открытым кодом, один из самых уважаемых инструментов в своём классе. Она шифрует всё на стороне клиента (AES-256 по умолчанию), дедуплицирует данные (копии компактны) и проверяет целостность по хешам — то есть повреждение обнаруживается, а не восстанавливается молча. Работает на Linux, Windows и macOS, умеет писать во множество хранилищ (локально, SFTP, REST-сервер, S3, Backblaze B2, Azure, Google Cloud и др.), прошла независимый аудит. Коротко: просто, надёжно, безопасно.

restic защищает репозиторий паролем. Этот гайд отвечает на главный вопрос: где хранить этот пароль? Если на диске, укравший сервер получит и его. Поэтому мы заставляем ключ Token2 FIDO2 выдавать пароль.

Как это работает

Расширение FIDO2 hmac-secret превращает ключ Token2 в детерминированный генератор секрета: для фиксированных credential и salt ключ всегда возвращает один и тот же 32-байтовый секрет — но только после PIN + касания и только с этого физического ключа. Этот секрет и есть пароль репозитория restic, поэтому он нигде на диске не лежит. Нет ключа → бэкапы это нечитаемый шифротекст.

Проверено с ключами Token2 FIDO2.1 с расширением hmac-secret и заданным PIN (напр. серии PIN+ / Molto2 / T2F2). Если PIN не задан — fido2-token -S <устройство>. Совместимые ключи: token2.com/c/fido2-keys.

Предусловия (Linux)

sudo apt install fido2-tools restic openssl     # Debian/Ubuntu
fido2-token -L                                  # список ключей → устройство, напр. /dev/hidraw0

Ниже устройство обозначено как $DEV.

Шаг 1 — Регистрация ключа (один раз)

Создаём FIDO2-credential с включённым hmac-secret, требуя проверку пользователя (PIN), и сохраняем его credential и фиксированный salt. Вместе с ключом они воспроизводят секрет; без ключа — бесполезны.

DEV=$(fido2-token -L | head -1 | cut -d: -f1)      # напр. /dev/hidraw0
sudo install -d -m 700 /etc/restic-fido2

printf '%s\n%s\n%s\n%s\n' \
  "$(head -c32 /dev/urandom | base64)" "restic-backup" "restic" "$(head -c16 /dev/urandom | base64)" \
  | fido2-cred -M -h -v "$DEV" | fido2-cred -V -h -o /tmp/cred.out
#            ^ -h = hmac-secret   ^ -v = проверка пользователя (PIN)   (сейчас спросит PIN + касание)

sudo sed -n 1p /tmp/cred.out | sudo tee /etc/restic-fido2/credential >/dev/null   # id credential
head -c32 /dev/urandom | base64 | sudo tee /etc/restic-fido2/salt      >/dev/null  # фиксированный salt
sudo rm -f /tmp/cred.out; sudo chmod 600 /etc/restic-fido2/*
Сделайте резервную копию /etc/restic-fido2 и зарегистрируйте второй ключ Token2 (повторив шаг) — credential нельзя скопировать между ключами, потеря единственного ключа = потеря доступа.

Шаг 2 — Хелпер, выдающий пароль

Маленький скрипт спрашивает ключ (PIN + касание) и печатает выведенный секрет. Он передаётся в любой инструмент через stdin, чтобы секрет не попадал в командную строку. (restic читает его через --password-command.)

sudo tee /usr/local/bin/restic-fido2-pass.sh >/dev/null <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
DIR=/etc/restic-fido2
DEV=$(fido2-token -L | head -1 | cut -d: -f1)
printf '%s\n%s\n%s\n%s\n' \
  "$(head -c32 /dev/urandom | base64)" "restic-backup" \
  "$(cat "$DIR/credential")" "$(cat "$DIR/salt")" \
  | fido2-assert -G -h -v "$DEV" | tail -n1     # последняя строка = 32-байтовый hmac-секрет (base64)
EOF
sudo chmod 700 /usr/local/bin/restic-fido2-pass.sh

Проверка — запустите дважды; с PIN + касанием каждый раз выдаст одинаковую строку (ключ даёт стабильный секрет):

sudo /usr/local/bin/restic-fido2-pass.sh
sudo /usr/local/bin/restic-fido2-pass.sh

Шаг 3 — Проверка: зашифровать и расшифровать файл ключом

Докажем, что ключ реально защищает данные. Шифруем файл секретом из ключа, затем расшифровываем — каждая операция требует PIN + касания. Неверным паролем файл не открыть, что доказывает: ключ действительно нужен. (Внутри restic делает ровно то же тем же секретом.)

echo "Token2 secret $(date)" | sudo tee /tmp/plain.txt

# шифрование (PIN + касание) — секрет идёт через stdin, в командной строке не виден
sudo /usr/local/bin/restic-fido2-pass.sh \
  | sudo openssl enc -aes-256-cbc -pbkdf2 -salt -pass stdin -in /tmp/plain.txt -out /tmp/cipher.bin
sudo od -A x -t x1z /tmp/cipher.bin | head -3   # → нечитаемый шифротекст

# расшифровка (снова PIN + касание → тот же секрет из ключа)
sudo /usr/local/bin/restic-fido2-pass.sh \
  | sudo openssl enc -d -aes-256-cbc -pbkdf2 -pass stdin -in /tmp/cipher.bin -out /tmp/decrypted.txt
sudo cat /tmp/decrypted.txt               # → исходный текст вернулся

# неверный пароль не откроет файл (ключ обязателен):
echo wrong-password \
  | sudo openssl enc -d -aes-256-cbc -pbkdf2 -pass stdin -in /tmp/cipher.bin -out /dev/null   # → "bad decrypt"

Укажите restic на тот же хелпер: restic --password-command /usr/local/bin/restic-fido2-pass.sh … — и каждый init / backup / restore будет под защитой ключа Token2.

Заметки и оговорки

  • Задайте PIN на ключе (fido2-token -S $DEV) — от него зависит проверка пользователя.
  • Держите проверку пользователя единообразной: всегда -v. hmac-секрет различается между проверкой с PIN и без — это изменит выведенный пароль.
  • Зарегистрируйте запасной ключ и храните в сейфе; credential нельзя скопировать между ключами.
  • Путь устройства (/dev/hidrawN) может меняться; хелпер определяет его заново через fido2-token -L. Для нескольких ключей выбирайте по строке продукта.
  • Интеграция «сообществом» (у restic нет встроенного FIDO2); проверьте на своей модели Token2 перед продакшеном.
