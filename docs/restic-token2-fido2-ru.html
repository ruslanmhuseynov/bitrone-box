Шифрование restic-бэкапов аппаратным ключом Token2 FIDO2

Сделать репозиторий restic, который можно расшифровать и восстановить только физическим ключом Token2 — с вводом PIN и касанием.

Bitrone · soc.bitrone.az · на базе libfido2 / pam_u2f · для ключей Token2 FIDO2.1 (hmac-secret, задан PIN)

restic не поддерживает FIDO2 напрямую — он открывает репозиторий паролем или файлом-ключом. Поэтому мы заставляем ключ Token2 выдавать этот пароль. Показаны два подхода: Метод A (hmac-secret) — ключ и есть ключ (рекомендуется, криптографически); Метод B (pam_u2f) — ключ авторизует операцию (проще, это гейт).

Проверено с ключами Token2 FIDO2.1, поддерживающими расширение hmac-secret и с заданным PIN (напр. серии PIN+ / Molto2 / T2F2). Если PIN ещё не задан — fido2-token -S <устройство>.

Предусловия (Linux)

sudo apt install fido2-tools restic          # Debian/Ubuntu
fido2-token -L                               # список ключей → запомнить устройство, напр. /dev/hidraw0

Ниже устройство обозначено как $DEV.

Метод A — ключ выводит пароль репозитория (hmac-secret)

Расширение FIDO2 hmac-secret превращает ключ в детерминированный генератор секрета: для фиксированных credential и salt ключ каждый раз возвращает один и тот же 32-байтовый секрет — но только после PIN + касания и только с этого физического ключа. Этот секрет используется как пароль репозитория restic через --password-command.

Секрет зависит от того, выполнялась ли проверка пользователя (PIN), поэтому мы всегда её запрашиваем (-v). Это и делает PIN обязательным, и сохраняет секрет стабильным.

1. Регистрация ключа (один раз)

DEV=$(fido2-token -L | head -1 | cut -d: -f1)      # напр. /dev/hidraw0
sudo install -d -m 700 /etc/restic-fido2
RP="restic-backup"                                  # идентификатор RP (любая постоянная строка)

# создать credential С hmac-secret, требуя проверку пользователя (PIN)
printf '%s\n%s\n%s\n%s\n' \
  "$(head -c32 /dev/urandom | base64)" "$RP" "restic" "$(head -c16 /dev/urandom | base64)" \
  | fido2-cred -M -h -v "$DEV" | fido2-cred -V -h -o /tmp/cred.out
#            ^ -h = hmac-secret   ^ -v = проверка пользователя (PIN)   (сейчас спросит касание + PIN)

sudo sed -n 1p /tmp/cred.out | sudo tee /etc/restic-fido2/credential >/dev/null   # id credential
head -c32 /dev/urandom | base64 | sudo tee /etc/restic-fido2/salt      >/dev/null  # фиксированный salt
sudo rm -f /tmp/cred.out
sudo chmod 600 /etc/restic-fido2/*
credential и salt храните надёжно (и сделайте резервную копию): с ними и ключом пароль воспроизводится; без ключа они бесполезны. Потеря ключа = потеря доступа, поэтому зарегистрируйте второй ключ Token2 и держите его в сейфе.

2. Хелпер, выдающий пароль

/usr/local/bin/restic-fido2-pass.sh:

#!/usr/bin/env bash
# Печатает пароль репозитория restic, выведенный из ключа Token2 (нужны PIN + касание).
set -euo pipefail
DIR=/etc/restic-fido2
DEV=$(fido2-token -L | head -1 | cut -d: -f1)
printf '%s\n%s\n%s\n%s\n' \
  "$(head -c32 /dev/urandom | base64)" "restic-backup" \
  "$(cat "$DIR/credential")" "$(cat "$DIR/salt")" \
  | fido2-assert -G -h -v "$DEV" | tail -n1      # последняя строка = 32-байтовый hmac-секрет (base64)
sudo install -m 700 restic-fido2-pass.sh /usr/local/bin/restic-fido2-pass.sh

3. Создание и использование репозитория

export RESTIC_REPOSITORY=/srv/backups/myrepo         # либо rest:…, s3:…, sftp:… и т.д.
restic --password-command /usr/local/bin/restic-fido2-pass.sh init          # создать репо
restic --password-command /usr/local/bin/restic-fido2-pass.sh backup /data  # бэкап
restic --password-command /usr/local/bin/restic-fido2-pass.sh restore latest --target /restore

Каждый вызов спросит PIN, затем касание. Нет ключа → restic не откроет репозиторий.

Метод B — ключ авторизует операцию (гейт pam_u2f)

Проще: у репозитория обычный пароль, а ключ Token2 (PIN + касание) нужен, чтобы запустить восстановление/расшифровку. Хорош как второй фактор и от случайного доступа; но пользователь с root на хосте может его обойти, и пароль по-прежнему лежит на диске.

1. Регистрация

sudo apt install libpam-u2f pamtester
sudo pamu2fcfg -o pam://restic -i pam://restic | sudo tee /etc/restic-u2f_keys
sudo chmod 600 /etc/restic-u2f_keys       # касание (+ PIN) во время регистрации

2. PAM-сервис /etc/pam.d/restic-restore — требовать PIN + касание

auth  required  pam_u2f.so authfile=/etc/restic-u2f_keys origin=pam://restic appid=pam://restic cue pinverification=1
auth  required  pam_permit.so

pinverification=1 делает PIN обязательным; cue показывает запрос касания.

3. Гейт в скрипте восстановления

pamtester restic-restore "$USER" authenticate || { echo "ключ не подтверждён"; exit 1; }
restic -r "$REPO" restore latest --target /restore

Заметки и оговорки по Token2

  • Задайте PIN на ключе (fido2-token -S $DEV) — от него зависят и проверка пользователя в Методе A, и опция pinverification=1.
  • Держите проверку пользователя единообразной в Методе A: всегда используйте -v. hmac-секрет различается между проверкой с PIN и без неё — их смешивание изменит выведенный пароль.
  • Зарегистрируйте запасной ключ. FIDO2-credential нельзя скопировать между ключами — заведите второй ключ Token2 и храните в сейфе. Потеря единственного ключа = потеря доступа.
  • Путь устройства (/dev/hidrawN) может меняться; хелпер определяет его заново через fido2-token -L. Для нескольких ключей выбирайте по строке продукта.
  • Это неофициальная, «сообществом» интеграция (у restic нет встроенного FIDO2); проверьте на своей модели Token2 перед использованием в проде.
